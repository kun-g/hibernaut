# 系统 Steward 需求

这份文档管系统 Steward：接入新项目、检查和补齐各项目的 Steward 配置。怎么做见 [设计文档](../architecture.md)；用词以 [glossary.md](../glossary.md) 为准。每条都经用户认过，改之前先问。

## 要的结果

有一个系统级的 Steward 负责管理，比如新项目接入时帮它配置默认的 Steward。

不归这里：重启、升级和部署 Hibernaut 归运维；改服务器入口的路由归部署；密钥归用户；某件活派给哪个项目归全局 Steward，项目内派给谁归项目 Steward。

## 要求

### 什么算「接入时帮它配置」

**R1 用户在单聊里说「把 owner/repo 接进来」，之后这个项目能接活，主入口由 Steward 先看，子队列由 SDE 做，用户收到一份列明做了哪几步的答复。** 为什么：没有 Steward 的项目，一句提问也会直接开一个 SDE。

**R2 新项目默认开 PR、不自动合并，带一句说明，全局 Steward 随即能派活给它。** 为什么：合并不可撤回，默认留给人；缺派活名单的项目只能手工投递。

**R3 用户对同一个仓库再说一次接入，已有的不重复建、不覆盖。** 为什么：用户手改过的配置不能被默认值冲掉。

**R4 用户没说清仓库或要哪个名字，只问一句，不猜。** 为什么：猜错会在别人名下的仓库或错误的入口上动手。

### 什么算「管理」

**R5 用户问各项目缺什么，答复按项目列出缺的：Steward、说明、派活名单。** 为什么：缺哪项现在要逐段读配置才看得出。

**R6 用户说补上，直接改好并生效，不需要审批，答复列明改了什么、怎么退回。** 为什么：改动能一步退回，审批只增加等待。

**R7 要改服务器入口路由、或在不属于用户的仓库上建标签等，只列出来，不动手。** 为什么：影响用户以外的人或线上入口。

### 什么算「负责」

**R8 做不成时（仓库连不上、名字冲突、配置不合法）用户收到原因和停在哪一步，线上配置保持原样。** 为什么：半截配置会让所有项目停摆。

**R9 用户照旧跟全局 Steward 说，结果回到同一个单聊。** 为什么：多一个入口就多一处要记。

## 约束

**C1 系统 Steward 没有命令行，也不能任意编辑文件，只能做上面这些事。** 来自：系统安全。
为什么：它读得到外来文字，能任意执行就等于把主机交出去；代价是新能力要先开发。

**C2 密钥和令牌的值不进入它的上下文、答复和日志。** 来自：零真实密钥契约。

**C3 它不能改执行器、启动器、权限、交付检查命令、凭据，也不能改自己和别的系统入口的绑定。** 来自：系统安全。
为什么：这些键能让它给自己加权限或执行任意命令；代价是这些仍由人改。

**C4 管聊天的全局 Steward 没有改系统配置的能力，只能转交。** 来自：系统安全。
为什么：聊天的上下文最杂，权限分开后一处被带偏不等于配置被改；代价是多一次转手。

**C5 写配置前整份校验，有备份，写入不会留下半份；人同时改了就放弃并说明。** 来自：运行稳定。

**C6 除用户单聊经全局 Steward 转来的和本机运营者投的，别的来源到不了系统 Steward。** 来自：系统安全。

## 衡量

| 指标 | 量的是 | 目标 | 现在 |
|---|---|---|---|
| 缺 Steward 的项目数 | 接入时是否配好 | 0 | 0（上线前人工补齐） |
| 写坏线上配置的次数 | C5 | 0 | 未上线 |

## 按默认定

- 系统 Steward 的入口是 `sys:ops`，agent 名 `ops`。
- 默认 Steward 由接入脚本写入，不靠 agent 判断。
